    \subsection{Intro}
    \subsection{Exploring RISCV}
      RISCs first implemented in 1980s. RISC-V is 5th gen RISC. RISCV Exchange is a website detailing list of available RISCV implementations/resources.
      RISC-V came out of Berkeley Parallel Computing Lab.
      Tim Berners-Lee revolutionized major internet protocol standards (URL, HTML, HTTP, W3C).
      RISCV implements creative common license to allow the spec to remain open. SW/HW artifacts implement BSD/MIT licenses so that RISCV has permissive open usage.
      RISC-V Base Inteter ISA has 40 instructions.
      David Patterson (Berkeley) and John Hennessy (Stanford) received Turing award for RISCV in 2017.
      RISCV has promise due to commitment to completely open architecture/source/spec/standard.
      RISCV ASPIRE Lab (run by Krste Asanovic, successor to David Patterson's Par Lab) received DARPA funding, but did not restrict technology's dissimination.
    \subsection{RISCV International}
      Does not build HW, but rather helps HW/SW teams/companies to build RISCV systems themselves through a clear and simple ISA.

    \subsection{RISCV Spec}
      First volume spec defines unprivileged ISA extensions. Second volume spec defines privileged archeticture.
      \subsubsection{Modular ISA}
        A green card (reference manual) of the extensions can be found \href{http://riscvbook.com/greencard-20181213.pdf}{here}.
        \newline
        The basic ethos of riscv is that it is a "modular" ISA. There is a mandatory base ISA and multiple optional extensions. This differs from ARM in that ARM cortex M4 ISA conains all of the instruction in M3, which the M3 contain all the M0+ instructions. There is no way to opt-out of the M3-specific instructions and just contain, say, M4 and M0+.
        \newline
        Extensions:
        \begin{itemize}
          \item \textbf{I}: Integer, the only \textit{required} module. Contains all necessary basic operations.
          \item \textbf{E}: Embedded, a version of I with fewer registers for embedded targets.
          \item \textbf{M}: Integer multiplication and division.
          \item \textbf{P}: Packed-SIMD instructions.
          \item \textbf{A}: Atomic instructions.
          \item \textbf{C}: Compressed instructions. This provides an alternative 16-bit encoded subset of RV32I instructions (which are normally 32 bit).
          \item \textbf{F}: Single-precision floating point instructions.
          \item \textbf{D}: Double-precision floating point instructions.
          \item \textbf{Q}: Quad-precision floating point instructions.
          \item \textbf{G}: "General" shorthand for IMAFD, a very popular combination of modules.
          \item \textbf{Zfh}: Half-precision floating point instructions.
          \item \textbf{BF16}: BFloat16-precision
          \item \textbf{Zfa}: Additional floating point instructions which are not covered by other modules.
          \item \textbf{Zfinx}: Floating point instructions which occur in integer registers.
          \item \textbf{Zficsr}: Manipulating CSRs.
          \item \textbf{Zifencei}: Instruction-memory synchronization.
          \item \textbf{C}: compressed instructions.
          \item \textbf{H}: hypervisor instructions.
          \item \textbf{L}: decimal floating-point operations.
          \item \textbf{Zc}: code size reduction.
          \item \textbf{B}: Bit manipulation.
          \item \textbf{V}: Vector operations.
          \item \textbf{Crypto}: Cryptographic instructions
          \item \textbf{CFI}: Control flow integrity.
          \item \textbf{Zilsd}: Load/Store pair for RV32
        \end{itemize}
      \subsubsection{ISA Primer}
        \begin{description}
          \item[ISA]
            Instruction Set Architecture. An abstract model of a computer. Implentations are things like CPU/GPU/XPU/TPU.
        \end{description}
        RISCV is maintained by a member organization which is free to join and has permissive open-source licenses. This prevents any one individual/organization from monopolizing the RISCV spec.
        \paragraph {Development Model:}
          \begin{enumerate}
            \item Spec begins as a "Task Group" approved by the TSC (Technical Steering Committee).
            \item After approval, begin public work on GitHub. Docs developed using AsciiDoc. Only members may contribute pull-requests, but anyone may submit issues.
          \end{enumerate}

      \subsubsection{RV32I: Base Integer ISA}
        Specifies 32 CPU registers, all 32b wide, plus the PC. R0 always reads 0. ABI (Application Binary Interface) specifies how each register is used.
        \begin{itemize}
          \item Add/Subtract
          \item Bitwise logical operations
          \item Load/Store
          \item Jumps
          \item Branches
        \end{itemize}
        \begin{table}[ht]
          \centering
          \begin{tabular}{|c|c|c|c|}
            \hline
            Register & ABI Name & Description                       & Saver  \\
            \hline
            R0       & zero     & Hard-wired 0                      & -      \\
            R1       & ra       & Return address                    & Caller \\
            R2       & sp       & Stack pointer                     & Callee \\
            R3       & gp       & Global pointer                    & -      \\
            R4       & tp       & Thread pointer                    & -      \\
            R5       & t0       & Temporary/alternate link register & Caller \\
            R6-7     & t1-2     & Temporaries                       & Caller \\
            R8       & s0/fp    & Saved register/frame pointer      & Callee \\
            R9       & s1       & Saved register                    & Callee \\
            R10-11   & a0-1     & Function arguments/return values  & Caller \\
            R12-17   & a2-7     & Function arguments                & Caller \\
            R18-27   & s2-11    & Saved registers                   & Callee \\
            R28-31   & t3-6     & Temporaries                       & Caller \\
            \hline
          \end{tabular}
          \caption{RV32I ABI}
        \end{table}
      \subsubsection{CSRs: Control and Status Registers}
        Separate bank of registers w/ 12b address space (thus 4096 max). Contains things like timers, counters, flags, mfg. info, etc. They are the primary mechanism by which software controls hardware. This is crucial for RISCV programmers. \textbf{Zicsr} extension contains many of the CSR manipulation instructions: CSRRW, CSRRS, CSRRC, etc. The most important CSRs:
        \begin{itemize}
          \item \textbf{mstatus}: Machine Status Register. Controls operating priv level, ISR\_Enable/Disable flags and other processor control flags.
          \item \textbf{mepc}: Machine Exception Program Counter. Stores PC of instruction that caused an exception (or an interrupt in machine mode).
          \item \textbf{mtvec}: Machine Trap-Vector Base Address.
          \item \textbf{mcause}: Machine Cause Register. Reason for most recent interrrupt/exception. Distinguishes interrupts from exceptions.
          \item \textbf{misa}: Machine ISA Register. Specifies which ISAs are supported and what the base ISA is.
        \end{itemize}
      \subsubsection{Extensions}
        Each extension is maintained by a \textit{Task Group} (e.g. Crypto, BExtension, VExtension).
      \subsubsection{M: multiplication and division}
        Common for low-power/small processors to omit M since multiplication can be performed in software using shifts/adds.
      \subsubsection{F and D: floating point and double precision}
        1b: sign, 0 is positive, 1 is negative \newline
        8b: exponent, 0 is 2e-126, every bit in adds to exponent. Min is -127, max is 127.\newline
        23b: mantissa (fraction), begins as 0, MSb is 0.5, then 0.25, 0.125, etc. where you add the fractions together. Min is 0, Max is very close to 1.\newline
        \begin{equation}
          val = sign * mantissa * 2^{exponent - 126}
        \end{equation}

          \centering

          \caption{FP32: single-precision floating point representation.}
        \end{figure}
      \subsubsection{C: Compressed Instructions}
        Alternative 16b encoding for instructions. Takes the 34 most popular instructions and encodes them in 16b. With this addition approx. 50\% of instructions can be compressed, leading to 25-30\% reduction in code size.
      \subsubsection{Unsupported Instructions}
        RISCV implementations can still execute instructions which are not in its ISA. When this happens an exception is thrown and the software running on the implementation must emulate the instruction in software.
    \subsection{RISCV ISA}
      \subsubsection{Instruction Encoding}
        \begin{itemize}
          \item 1x 32b PC
          \item 32x 32b Registers (R0-R31)
          \item 40x Unique 32b unpriv instructions in 6 formats:
            \begin{itemize}
              \item R: Register. 2 source registers and 1 dest register.
              \item I: Immediate. Anything involving an immediate value.
              \item S: Store. Subset of I-Type. Store to memory. Involves source register, immediate offset, and base addr register specifying the memory location.
              \item B: Branch. Conditionals, compares two registers.
              \item U: Upper Immediate. Sets only the upper bits of a register to a constant.
              \item J: Jump. Unconditional jumps.
            \end{itemize}
        \end{itemize}
        \begin{figure}[ht]
          \centering
          \includegraphics[width=\textwidth]{images/rv_encoding.png}
          \caption{Unpriv Encoding Format}
        \end{figure}
      \subsubsection{Immediates and Addresses}
        Any instruction other than R-type may contain an immediate. All immediates decode to 32b values, but encoding varies by instruction.

      \subsubsection{Irregular design decisions}
        \begin{itemize}
          \item No Flag or Condition Register
          \item R0 is hard-wired to 0
          \item No way to specify a 32b immediate in a single instruction
          \item No dedicated mul/div in the base ISA (RV32I)
          \item Many missing basic instr. These are all special-cases of existing instr. e.g.
            \begin{itemize}
              \item jmp is just jal w/ write to R0
              \item nop is the same as addi R0,R0,0
              \item not is just xori with -1 immediate (all 1's)
              \item mov is just add r1,r2,0
            \end{itemize}
          \item No SP by default, this is defined by the ABI.
          \item No push/pop to stack. This is achieved by a combination of load/store/add/sub instr.
          \item No subroutine "call" and "return" instructions. These are available as pseudoinstr of jal.
        \end{itemize}

      \subsubsection{M-Mode (Machine-level)}
        lowest-level mode, first mode entered after boot. Can be used for expensive/difficult features e.g. watchdog timer.
        \begin{itemize}
          \item \textbf{NMI} Non-Maskable Interrupt. Each has a "mcause" register associated. Do not reset HW state, so can provide more context for debugging.
          \item \textbf{PMA} Physical Memory Attributes. Rules that define the addressability and chmod/rwe permissions of different memory regions.
          \item \textbf{PMP} Physical Memory Protection. Not a fully no-trust envorintment, but can be used to create one. Limits physical address space accessible to a hardware thread (hart).
        \end{itemize}

      \subsubsection{S-Mode (Supervisor-level)}
        Hardware restriced. Really only has access to timers and inter-processor interrupts. Defined by the SBI (Supervisor Binary Interface). Uses things like SFENCE.VMA to synchronize updates to memory-contained data structures so subsequent reads are coherent. Supports any of 32b, 39b, and 48b VM addressing.

      \subsubsection{Reminder: Assembly Instruction Set}
        \begin{lstlisting}[language=RISCV]
add   rd, rs1, rs2
auipc rd, imm         # adds 20b immediate (lshifted 12b) to the PC.
jal   rd, offset      # Writes PC+4 to rd and jumps to pc+sext(offset)
jalr  rd, offset(rs1) # Writes PC+4 to rd and jumps to rs1+offset
lw    rd, offset(rs1) # Loads 4B from from rs1+offset into rd
lb    rd, offset(rs1) # Loads 1B from from rs1+offset into rd
lui   rd, imm         # leftshift imm 12 then add to rd.
addi  rd, rs, imm     # rs+imm = rd
sw    rs2, offset(rs1) # Stores rs2 to rs1+offset (word)
sb    rs2, offset(rs1) # Stores rs2 to rs1+offset (byte)
        \end{lstlisting}
      \subsubsection{Reminder: PseudoInstructions}
        Most of the pseudoinstructions are just special cases of existing instructions using x0 (0) or x1 (retAddr).
        \begin{lstlisting}[language=RISCV]
nop               # addi, x0, x0, 0
beqz  rs, offset  # beq   rs, x0, offset
j     offset      # jal   x0, offset
jal   offset      # jal   x1, offset
jr    rs          # jalr  x0, 0 (rs)
ret               # jal   x0, 0(x1)
lla   rd, symbol  # auipc rd, symbol[32-12]; addi rd, rd, symbol
li    rd, imm     # lui   rd, imm[32-12]; addi rd, rd, imm
mv    rd, rs      # addi  rd, rs, 0
not   rd, rs      # xori  rd, rs, -1
bgt   rs, rt, off # blt   rt, rs, off (offset)
call  offset      # auipc x1, offset[32-12]; jal x1, offset[11:0](x1)
      \end{lstlisting}
